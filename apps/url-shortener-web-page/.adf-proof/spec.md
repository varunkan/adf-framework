## Approach

- Use a single endpoint `POST /shorten` for creation; validate input length and reject non‑HTTPS URLs to prevent malicious redirects.  
- Generate short codes via deterministic hashing (e.g., base62) to ensure uniqueness without external DB queries, reducing failure points.  
- Store mappings in an in‑memory object (`Map<String,String>`), clearing on graceful shutdown; implement a watchdog timer to purge stale entries and avoid unbounded memory growth.  
- Frontend: minimal HTML with input field, “Shorten” button, and result display; backend serves `/short/{code}` via short‑code hash lookup and redirects to original URL only after validating the code exists in the map.
