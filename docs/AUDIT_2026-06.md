# ADF Code Audit — Executive Remediation Plan

**Prepared by:** Engineering Director
**Scope:** ADF build/orchestration framework (Python runner, Dart orchestration server, Flutter dashboard, generated-app templates)
**Basis:** Fortune-500 third-party audit; every finding below was independently reproduced against the live code.

---

## 1. Executive Summary

**Is the build path trustworthy? No — not yet.** The pipeline produces a *cryptographically sealed* "Proof of Build" that attests to outcomes it never actually verifies. The headline risk is **a green checkmark that lies**: an app can render a blank white screen, ship a world-known session secret, or run on absent tests, and still pass verification with a sealed proof saying it was checked. This is the same defect class as the feature-id bug the team already shipped — *a control signal trusted without being validated* — and it recurs across the runner, the governance gates, and the dashboard.

Three things compound it:

1. **The verification chain certifies transport, not outcome.** Every React verify stage proves the *server returns bytes* (`tsc` compiles, `vite` bundles, vitest hits the API, a TCP socket answers `200`). Not one stage executes the bundle in a browser, so the single artifact a user sees — the rendered page — is asserted by nobody. A non-rendering SPA is "verified."

2. **A localhost service that generates *and executes* arbitrary code ships with wildcard CORS and zero authentication.** Any website the operator visits can drive the runner into writing and running code on their machine, with the operator's full environment (including `ANTHROPIC_API_KEY` / `NVIDIA_API_KEY`) inherited by that code. This is a drive-by RCE, confirmed end-to-end.

3. **Governance gates seal claims they never check.** Phase gates 1/5/6 (including `tests_red`) flip to `true` and get hash-chained as "passed" with no machine validation; an unknown approval `decision` value silently bypasses every gate; the `no_secrets` verdict passes on a hardcoded HMAC secret. The proof chain lends unearned credibility to unverified state.

The good news: the architecture is sound and the fixes are concentrated. The **single highest-leverage change** — adding one headless-browser render stage — closes *four* confirmed defects at once and is the gating dependency for "defect-free generated apps." The security fixes are small and well-scoped. There is no rewrite here; there is a focused two-week hardening sprint.

**Trust verdict:** Do not represent build output as "verified" to end users until the render stage (§4) and the auth/CORS boundary (§2, SEC-1) land. After P0, the build path becomes trustworthy for the cases it claims to cover.

## 3. "10x Faster" Performance Section

The build path currently does a **full, from-scratch dependency install per app** with no shared store, then re-runs the entire verify pipeline on every self-heal attempt. The wins are concrete and stack multiplicatively.

| Win | Where | What it saves | Rough speedup |
|-----|-------|---------------|---------------|
| **Kill `npm ci` from the hot path** — `scaffold_app` skips `node_modules` (`_SKIP_DIRS`, `agent_runner.py:363`), so every fresh app does a from-scratch install. Copy/hard-link the template's warmed `node_modules` (or switch to pnpm with a content-addressed store symlinked per app). | `agent_runner.py:356-371,724-728` | Removes the install entirely (no-op verify) **and** the **114 MB duplicated per app** on disk (measured across every built app). | **10–50×** on first build (cold CI: 30–90s → ~0s install). pnpm also collapses disk to one copy. |
| **Cheapest-first, short-circuit verify** — run `tsc --noEmit` alone first; only build+test if types pass. Most LLM failures are type errors, yet attempt 2 currently re-runs the *full* `vite build` + vitest + node boot. | `agent_runner.py:716-738,1029-1054` | Avoids 2 redundant full-pipeline runs across the (default 3) self-heal attempts. | **2–3×** on the self-heal path (the common failure case). |
| **Persist Vite cache + collapse cold-starts** — wire `node_modules/.vite` across attempts; the 3 stages are 3 separate node cold-starts. | `agent_runner.py:716-738` | Incremental rebuilds; 3 cold-starts → 1. | ~1.3–2× on rebuild-heavy retries. |
| **Reuse one `HttpClient` per brain** — currently constructed and `close(force:true)`'d per LLM call, paying a full TLS handshake (~100–300ms RTT) on each of up to 3 self-heal round-trips. | `openai_compat_brain.dart:86,92`; `claude_api_brain.dart:93` | Amortizes TLS across generate+fix turns. | Few hundred ms × retries; free; matters under throughput. |
| **Decouple crew vs runner budgets** — the deterministic crew runs under a 30s/agent budget for ms-scale work; that same 30s default leaked into the runner where it *was* harmful. | `agent_crew.dart:35-38` | No runtime speedup, but prevents the cross-contamination that caused the timeout bug. | Correctness guardrail. |

**Headline:** Win #1 alone is **10×+ on first build and eliminates ~114 MB/app of disk bloat** — it removes the single biggest cost from the hot path with a trivial-to-medium change. Combined with cheapest-first verify, a typical generate-with-one-self-heal cycle drops from a multi-minute cold sequence to seconds.

## 4. Visual-Testing Plan (Defect-Free Generated Apps)

This is the **keystone of P0**. One new stage closes VER-1, VER-2, the e2e-gate substring check, *and* the medium-severity CSS/wire-up gaps — because all five share one root cause: **nothing ever executes the bundle in a browser.**

**Add `_react_visual_verify(app_root, port)` as the final stage of `_react_verify`**, running against the *already-booted* server (reuse the `_node_smoke_boot` port — do not re-boot):

1. **Render assertion** — drive headless Chromium (Playwright) to `GET /`, wait for network-idle, then assert:
   - `document.querySelector('#root').childElementCount > 0` **and** `innerText.trim().length > 0` (real content, not the empty shell) → catches blank `#root` / non-rendering SPA.
   - **Zero** `console.error` / `pageerror` events during load → catches React runtime + hydration crashes.
   - A **spec-derived primary element** exists (form/button/heading; fallback: "≥1 `button|input|h1`").
2. **Wire-up assertion** — capture the browser's network log during load; assert **zero failed (`≥400`/`net::ERR`) requests to `/api/*`**, and that the primary data element isn't stuck on a `Loading…` placeholder → catches the UI-calls-an-endpoint-the-server-doesn't-implement class that vitest (server-only, `environment:'node'`) structurally cannot see.
3. **CSS smoke** — `getComputedStyle` on a `#root` child shows non-UA-default background/padding, or stylesheet rule count > N → catches Tailwind emitting an empty stylesheet (broken `content` glob) that builds green but renders unstyled.

**Plumbing requirements (non-negotiable for adoption):**
- **Failures route into the existing `fix_messages` self-heal loop**, verbatim, exactly like build/test/boot failures — so the model fixes the right `src/**.tsx` file.
- **Degrade gracefully on missing Chromium** to honor the offline/zero-cost ethos: if the browser binary is absent, log a WARNING and skip (`ok=True`) **unless** `ADF_VISUAL_VERIFY=strict`. Default `=1` in CI; `=0` disables. A missing browser must not turn every build red.
- **Upgrade the e2e gate** (`scripts/test/e2e_react_app.py:238-241`) to the same render assertion. The current `'id="root"' in html and '/assets/' in html` substring check passes on a byte-identical shell whether or not the app mounts — it endorses the false signal *at the gate level*. Keep the substring as a cheap precondition, not the definition of "serves the SPA."
- **Soften the overclaiming docstrings** (`agent_runner.py:674,720` — "Authoritative", "end-to-end") until a render assertion actually backs them.

## Appendix: all confirmed findings (raw)

### [medium] npm ci on EVERY build with no warm/shared cache — full reinstall per app, 114MB duplicated per app, re-run on every self-heal attempt
- **file:** scripts/orch/agent_runner.py:724-728 + templates/react-vite-sqlite/.gitignore:1 + scripts/orch/agent_runner.py:362-371
- **root cause:** No shared dependency store. Each app gets an isolated full install instead of a hard-linked/symlinked shared store (pnpm-style) or a copied warm node_modules from the template. The CLAUDE/MEMORY note says 'N3 was deferred' — this is N3. Cost is ~1.7s with a warm global npm cache but 30-90s on a cold machine/CI, multiplied by every fresh app and every node_modules-less re-verify.
- **fix:** Three cheap wins, any of which is 10x on first build: (1) Have scaffold_app COPY the template's node_modules (or hard-link it) instead of skipping it, so npm ci becomes a no-op verification; (2) switch to pnpm with a shared content-addressed store (one copy on disk, symlinked into each app) — kills both the time and the 114MB-per-app disk bloat; (3) if staying on npm, set a persistent shared `--cache` dir + `--prefer-offline` and copy node_modules from a warmed template on scaffold. Option 1 is trivial and removes the install from the hot path entirely.

### [critical] verify_app never renders the React app — a white screen / runtime error / blank #root passes as 'verified'
- **file:** scripts/orch/agent_runner.py:716-738
- **root cause:** The verify pipeline treats 'the server returns bytes' as a proxy for 'the app works'. The one artifact a user actually sees — the rendered DOM produced by executing the built JS bundle in a browser — is never executed during verification. A green verify therefore says nothing about whether the page renders.
- **fix:** Add a 5th, authoritative stage to _react_verify after _node_smoke_boot: a headless-browser render assertion against the SAME booted node server. Concretely (see design below): launch the already-running server on a free PORT, drive a headless Chromium (Playwright) to GET /, wait for network-idle, then assert (a) document.querySelector('#root').childElementCount > 0 and innerText.trim().length > 0 (root has real content, not the empty shell), (b) zero console.error / pageerror events were emitted during load (catches React runtime + hydration errors), (c) the spec's primary UI element exists (e.g. a form/button/heading — derive a selector list from the spec, fall back to 'at least one button or input or h1'). Fail the stage with the captured console errors verbatim so the self-heal loop (fix_messages) gets the real failure, exactly as it does for build/test/boot failures today.

### [critical] _node_smoke_boot's GET / 200 check is satisfied by the static HTML shell — it cannot detect a non-rendering SPA
- **file:** scripts/orch/agent_runner.py:673-707
- **root cause:** Confusing 'server can serve the index.html shell' (always true once dist/ exists) with 'the app renders'. urllib reads the literal response body; it has no JS engine, so client-rendered content is invisible to it.
